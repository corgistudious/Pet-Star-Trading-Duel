# Pet Star web client

React 18 + TypeScript + Vite single-page app for **iPhone Safari** and desktop browsers. It talks to the existing
ASP.NET Core backend: same REST API, rules, artwork and localization as the Unity client. The server stays
authoritative for every balance, card, roll and battle; the client only renders and asks.

## Run locally

```bash
npm ci
cp .env.example .env.local     # VITE_API_BASE=http://localhost:5080
npm run dev                    # http://localhost:5173
```

The backend Development config already allows `http://localhost:5173` and `:4173` for CORS and WebSocket Origin.

## Scripts

| Command | What it does |
|---|---|
| `npm run build` | typecheck → Vite build → Pages `_headers`/`_redirects` (CSP from `VITE_API_BASE`) → 25 MiB/file check |
| `npm test` | vitest unit tests (pack state machine, battle planning, deck rules, i18n, API client, realtime helpers, chart) |
| `npm run e2e` | Playwright against a **running real API** (`PETSTAR_E2E_API`, default `http://127.0.0.1:5080`) and Postgres (`PETSTAR_E2E_PG`) |

E2E projects:
- `iphone-chromium`: Chromium with iPhone 13 emulation (viewport, touch, DPR, user agent).
- `desktop-chromium`: Admin Panel / gift code / guild / language switch.

Real WebKit is not available in the build environment. Before launch, play through once on a real iPhone.

## Structure

- `src/api/`: fetch client (rotating refresh tokens, single-flight + cross-tab lock, idempotency keys), DTO types.
- `src/state/`: session (profile, server, balances), realtime WebSocket (ticket auth, backoff, refetch on
  reconnect), display catalog.
- `src/logic/`: pure, tested game-UI logic (pack tear/flip, battle planning, deck 3+2 rules).
- `src/screens/`: one file per screen. Routes are in `App.tsx`; secondary screens are lazy-loaded chunks.
- `src/i18n/`: loads the shared `en`/`vi` tables and overlays web-only strings from `web.ts`.
- `public/`: generated by `python3 tools/build_web_assets.py` (WebP art, `data/catalog.json`, `i18n/*.json`).
  Do not edit by hand.

## Viewport and PWA

- **Viewport:** Portrait 9:16 everywhere except PvE/PvP duels (Landscape 16:9), with a black rotate overlay on
  phones. See [../docs/viewport-rules.md](../docs/viewport-rules.md).
- **PWA:**
  - `manifest.webmanifest` (standalone, portrait, black theme, maskable icons).
  - `dist/sw.js` is generated at build time from the real output: precaches the shell, caches pet art on first
    view, never touches the API.
  - New versions wait for the player to tap "Reload". The first install never reloads the page.
  - Offline shows the shell and an offline notice; the session is kept.

## Security notes

- The refresh token is kept in `localStorage`, so it is exposed if any script injection happens. A strict CSP
  (`script-src 'self'`, no third-party scripts) mitigates this. Server-side rotation with reuse detection
  revokes the whole session family if a stolen token is replayed.
- No real-money purchases exist in the web client. The Rainbow Star store tab says so; `/api/iap/*` is disabled
  server-side.
