# Battle 3v3 (turn-based Pet battles)

Battle 3v3 replaces the old 20-card "Pet Battle Arena" completely. That card-battle mechanic (deck, Active/Bench, Energy Zone, prizes) has been removed from the server, the shared rules, the web client, Unity and the docs. Collection, 5-card packs, about 200 Pet designs, evolution and the two currencies (Sao Ngũ Sắc, Đậu Xanh Mini) are unchanged.

## Rules (engine `shared-contracts/Runtime/Rules/Team/`)

- Each side brings **3 different owned Pets**.
- **Unit stats:** HP / ATK / DEF / MAG / RES / SPD / EN.
  - HP, ATK, DEF and SPD come from the card (rarity, quality, upgrades).
  - MAG and RES are derived by role (percent of ATK and DEF):

    | Role | MAG | RES |
    |---|---|---|
    | striker | 60 | 80 |
    | guardian | 50 | 110 |
    | controller | 100 | 100 |
    | mage | 125 | 95 |
    | support | 115 | 115 |

- **EN:** start 50, max 100. A basic attack gives +15. Every Pet gets +10 at round end.
- **Kits:** every Pet has 4 actions:
  - basic attack (physical or magic);
  - skill (20–30 EN);
  - ultimate (50–60 EN, cooldown 3);
  - guard (priority 9, −50% damage this round).
- **Round flow:**
  1. Both players send orders for all living Pets. Orders stay hidden until both lock or the timer (`planSeconds`) ends.
  2. On timeout, the AI fills in the orders and the player gets a timeout strike. 3 strikes is a forfeit.
  3. The server locks the round and builds the queue: priority, then effective SPD (haste +), then a seeded tie-break.
- **Damage:** `power × A² / (A + D) / 100 × damageScalePct`, then:
  - element advantage ×150% or ×75%;
  - crit ×150%;
  - weaken −25%;
  - reduce passive;
  - guard −50%;
  - shield absorbs.
- **10 statuses:**

  | Status | Effect and limits |
  |---|---|
  | burn | DoT |
  | poison | DoT, stacks up to 3 |
  | stun | Skips the action. Hard control: 1 turn, then CC immunity |
  | freeze | Skips the action. Hard control: 1 turn, then CC immunity. Fire damage thaws it |
  | silence | Basic attack only |
  | weaken | −25% damage |
  | haste | +SPD |
  | regen | Heals over time |
  | taunt | Forces single-target attacks onto the taunting Pet; adds counter (reflects 20%) |
  | shield | Keeps the larger value; cap 60% of max HP |

  - Statuses other than poison refresh to the longer duration.
  - Cleanse removes negative statuses.
  - Round-end order: DoTs → regen → duration decrements → cooldowns → EN +10.
- **Passives:** drain, reduce, regen, rage, start_en, heal_bonus.
- **End of battle:**
  - all enemy Pets down (`knockout`);
  - both teams down at the same time (`both_down`, draw);
  - round 30 reached (`round_limit`): the higher remaining-HP share wins;
  - `surrender`;
  - `timeout` forfeit.
- **Randomness:** SplitMix64. The RNG state is part of the game state, so the server is authoritative and replays are exact.
- **Config:** `database/seed/team_battle.json` holds the version, config values, role table and 215 kits / 362 skills. It is generated by `tools/build_team_battle.py`. Each match stores the rules version it started with (`arena_card_versions`).

## Server (`backend/src/PetStar.Api`)

| Endpoint | Purpose |
|---|---|
| `GET /api/team/rules` | Rules JSON (same data the client engine uses) |
| `GET/POST /api/team/lineups`, `DELETE /api/team/lineups/{id}` | Saved 3-Pet teams (owned, different, not listed/locked) |
| `POST /api/team/pve {stageId, kind: pve\|boss\|practice}` | PvE. Boss: first enemy at 250% HP. Practice: no rewards |
| `POST/DELETE /api/team/queue {mode: casual\|ranked}` | Matchmaking (`TeamMatchmaker` runs every 2 s). Ranked caps growth at 145% |
| `POST /api/team/invite {uid}`, `POST /api/team/matches/{id}/accept\|decline` | Friend battle |
| `POST /api/team/rooms`, `POST /api/team/rooms/{code}/join` | Private room (6-character code) |
| `GET /api/team/active` | Resume after a reconnect (match, queue or room) |
| `GET /api/team/matches/{id}` | Per-player view. The opponent's unlocked plan and the RNG state are hidden |
| `POST /api/team/matches/{id}/actions {actionId, version, action}` | Plan or surrender. `actionId` is unique (idempotent). A stale version is rejected with `stale_state` |
| `GET /api/team/history`, `GET /api/team/matches/{id}/replay`, `GET /api/team/ratings` | History, deterministic replay, Elo (K=32) |
| `GET /api/trainer/catalog`, `GET/POST /api/trainer`, `PUT /api/trainer/companion`, `PUT /api/trainer/outfit` | Trainer: chosen once (`trainer_already_chosen`); default outfits only; outfits give no stats; companion must be an owned Pet |

- **WebSocket pushes:** `team_update`, `team_match_found`, `team_invite`.
- **Anti-cheat:** every order is validated by the server engine: EN, cooldown, silence, dead units, targets, duplicate orders. The client only sends intent.
- **Event log:**
  - `arena_events` records every applied action (unique action id);
  - snapshots are taken every 10 events;
  - rewards are written once per (match, member) through the economy ledger (`team:{id}:{idx}` references).

## Database (migration `20261123031047_Battle3v3Trainers`)

- **New tables:**
  - `team_lineups`, with a check constraint that the 3 cards are different;
  - `trainer_profiles`: character, appearance, outfit and companion IDs;
  - `trainer_outfits`: owned outfits.
- **Reused tables:** the `arena_*` tables, with the 3v3 state in the JSON columns.
- **Data note:** the migration empties `arena_queue` because old 20-card queue entries are invalid. Old 20-card deck tables are dropped.
- **Before Production:** take a backup and try it on a staging copy.

## Production (needs owner approval)

1. Back up the database.
2. Apply the migration on staging, then run the API tests against it.
3. Deploy the API image.
4. Deploy the web build.

Never deploy to the VPS or Cloudflare production without explicit approval. See [deployment.md](deployment.md).
